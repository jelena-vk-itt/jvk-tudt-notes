  1. Lambda expressions

    Lambda expressions

    A lambda expression

    • is an expression that defines a function i.e. a reusable piece of functionality
    • is returns (evaluates to) an anonymous function i.e. a function without a name
    • can be called as a function
    • can be assigned to a variable and thus get a name by which it can be called
    • can be passed in as an argument to another function and called by the parameter name
    • takes the form 
      lambda <parameter list> : <return value created from parameter>
    • takes arguments defined by the parameter list between lambda and the colon
    • returns the value to which the expression right of the colon evaluates
    • can use variables defined outside of it

    The main advantage of lambda expressions is that they can be used directly (anonymously i.e. without a name) wherever a function needs to be used once, e.g. when it is passed in as an argument to another function. This avoids source file littering with unnecessary code and improves readability.

  2. Functional programming

    Functional programming

    Python is not an exclusively functional language (such languages, e.g. lisp, are less common), but it includes several constructs that embody the paradigm.

    Characteristics of functional programming:

    • pure functions, which
      • always return the same output for the same input Python: not enforced 
        function add(x, y) { return x + y; }

// rather than

let x = 0;
function addToX(y) { x += y; return x; }
      • have no side-effects Python: not enforced 
        function add(x, y) { return x + y; }

// rather than

function add(x, y) { orderTakeaway(); return x + y; }
    • first-class functions (functions treated as objects) Python: yes 
      let aFunc = () => { return 'hello'; }
    • higher order functions (functions that have other functions as inputs or outputs) Python: yes 
      function makePowerFunc(p) { return x => x**p; }

// used:
let cube = makePowerFunc(3);
console.log(cube(5));
    • immutable data only Python: not enforced 
      let arr = [3, 5, 4, 1];
arr2 = arr.toSorted();
console.log(arr, arr2);

// rather than
arr.sort();
console.log(arr);

  3. Processing lists without loops

    Processing lists without loops

    A very useful paradigm that uses functional programming is the use of functions that process entire collections of elements. Rather than looping through the elements of the collection, we can specify a function (usually a lambda expression) that we want applied to each element and let the collection-processing function do the rest. The advantages of this approach are:

    • processing of lists (or other collections) without having to write loops
    • not having to create and keep track of variables holding intermediate results and values
    • focusing on what needs to be done with individual pieces of data, rather than the collection structure

    map

    Creates a new list by using a function to map each element of an existing array to a new element.

    # maps each number element to its square
number_list = [1, 2, 3]
mapped_values = map(lambda n : n**2, number_list)
new_number_list = list(mapped_values)

# maps each name to its initial letter
name_list = ['Alice', 'Bob', 'Con']
initial_list = list(map(name => name[0]))

    filter

    Creates a new list by using a predicate on each element to decide whether to include or exclude it.

    # filters in only even numbers
number_list = [1, 2, 3, 4, 5]
even_number_list =  list(filter (lambda n : (n % 2 == 0), number_list))

# filters in names that are shorter than 4 characters
name_list = ['Alice', 'Bob', 'Con', 'Derval']
short_name_list = list(filter(lambda name : len(name) < 4, name_list))

    reduce

    Creates a value by iteratively applying a 'reducing' operation to pairs of values from the list.

    from functools import reduce

# reduces by adding (calculates the sum)
number_list = [1, 2, 3, 4, 5]
reduce(lambda sum, val : sum + val, number_list, 0)

# concatenate names, separated by spaces
name_list = ['Alice', 'Bob', 'Con', 'Derval']
reduce(lambda text, val : text + " " + val, name_list, "")

    all, any

    These are two functions that perform specific reduce operations.

    The all function returns True if all the values in the passed-in list are or convert to True.

    The any function returns True if at least one of the values in the passed-in list are or convert to True.

    Chaining

    The methods above can be chained for more complex functionality.

    • map and filter can be placed in the middle of chains
    • reduce, all and any must be at the end of a chain
    #calculating space needed to print out the short names, separated by commas
names = ['Alice', 'Bob', 'Con', 'Derval', 'Evan']
reduce(lambda sum, nmlen : sum + 2 + nmlen, map(lambda name : len(name), filter(lambda name : len(name) < 5, names)), -2)

  4. List comprehensions

    List comprehensions

    List comprehensions are a construct that include both mapping and filtering. Their syntax is:

    [ expression for element in some_list if condition ]
    • The black text in the syntax specification constitutes the fixed parts of the comprehension, including keywords and brackets.
    • The blue italic text in the syntax specification are parts that need to be programmed in: the list that needs to be processed (some_list), the name to be used for an element of the list (element) and the expression that maps the element to a new element (expression).
    • The remaining part of the syntax (with gray background) is optional and represents the filter part of the comprehension, specifying the condition that an element must 'pass' to be included (condition).

    Comprehensions are considered easier to write, and read. There are some scenarios where map/filter is still more concise: when the mapping function is built in (e.g. len or int) and when multiple lists need to be transformed.
